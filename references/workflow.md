# 安全工作流

## 0. 环境准备

- 检查源文件、模板、当前系统、可用的 PPT 编辑工具和渲染/重开验证能力。按 [powerpoint-technical.md](powerpoint-technical.md) 选择适用路径。
- 如已有 PowerPoint MCP，可探测 `ppt_get_app_info` / `ppt_list_presentations`；如没有，评估现有 PowerPoint 或其他可靠的 PPTX 工具。安装 ppt-mcp、uv 或修改客户端配置须符合用户选择的环境和任务需求，不作为默认前置条件。
- 如无法可靠编辑并验证 PPT，仅交付内容草稿与修改清单，明确未生成或修改 PPT。

## 1. 接收与边界确认

- 确认源文件、最终文件名、病例资料来源、允许调整范围和交付路径。
- 模板选择：用户指定了已有 PPT（如某科室病例汇报）时，以该已有 PPT 为模板进行改造；未指定、或用户要求「根据模板生成」时，用文件系统把 skill 内通用模板 `templates/病例汇报_通用模板.pptx`（见 SKILL.md 约定常量）复制到目标 PPT 目录后作为起点，不直接编辑母版。
- 记录用户明确允许变更的页面/元素；未授权项默认保护。
- 病例资料来源：真实病例以操作者提供的详细病史、查体、检验、影像、诊断和治疗资料为唯一患者事实来源；未提供时可选用或编写虚构教学病例，但必须在 PPT 内标注“虚构教学病例”。按 [medical-content.md](medical-content.md) 区分两类资料，临床细节与结局须经审核。
- 若病史或检验资料不完整，列出缺口，不以“合理推断”补成患者事实。

## 2. 保护原件：先复制，后打开编辑副本

OneDrive/PowerPoint 的 AutoSave 可能实时写回当前文档。安全顺序必须是：

```text
源 PPT（只读基线）
  → 打开/检查
  → 立即 Save As 到同级或指定的临时副本
  → 验证标题栏、当前激活演示文稿和完整路径
  → 只编辑该副本
```

使用 skill 内母版模板（`templates/病例汇报_通用模板.pptx`，见 SKILL.md 约定常量）时：先用文件系统 `Copy-Item` 把母版复制到目标 PPT 目录并命名，再打开该副本编辑；母版本身永不打开、永不修改。

命名以 [SKILL.md](../SKILL.md) 的交付约定为准：工作副本 `NAME-科室-病例汇报_working.pptx`，最终版 `NAME-科室-病例汇报.pptx`。不要用笼统的 `test.pptx`，以免误覆盖。

若源文件已被 AutoSave 改动：立刻停止继续修改；保留当前状态；优先从版本历史、只读副本或云端版本恢复，再重新建立工作副本。不要用未经确认的版本覆盖原件。

## 3. 基线盘点

在改字前记录：

- 幻灯片数、顺序、节标题、页面比例、主题和母版线索；
- 每页背景、Logo、页码、页眉页脚、固定装饰和不可编辑对象；
- 文本框、表格、图片、图表、组合对象、备注、动画和切换；
- 溢出文本、低清图片、空白占位符和已存在的格式异常。

必要时截取编辑前预览，便于对照。只在目标副本中修改。

## 4. 建立统一病例数据源

先用结构化草稿统一所有数值、日期、单位、诊断名称与时间线，再写入任何页面。字段和核验规则见 [medical-content.md](medical-content.md)。

将每个结论回链至病例来源：病史、查体、化验、影像、病理或会诊记录。无法回链的内容不放入定论性页面。

## 5. 内容、布局与演示顺序

按“主诉/现病史 → 关键检查 → 诊断依据 → 处置 → 转归/反思”组织；若源模板顺序不同，除非获授权，不调整页面顺序，而在页面内部重组信息。页数不固定，内容过多时可在不破坏流程与视觉语言的前提下增加页面；列表/表格/卡片的行数与列数按需增减，不局限固定数量。

按 [layout-design.md](layout-design.md) 选择布局等级和动画；技术操作遇到格式风险时按 [powerpoint-technical.md](powerpoint-technical.md)。

## 6. 渐进保存与失败恢复

- 在完成一个章节或一批页面后保存工作副本；重大重排前额外生成带时间戳的恢复点。
- 一次只做可验证的变更；失败时撤销当前小批次或回到最近恢复点，而不是在损坏文件上叠加修补。
- 若某对象的编辑会破坏格式或无法可靠定位，保留原对象，另建最小替代元素，并记录原因。
- 若 PowerPoint、MCP 或 COM 失去连接，先保存可保存的工作副本、关闭异常会话、重新打开副本并核对页数与最后成功修改；不得假定未保存操作已生效。

## 7. 最终化

完成最终副本后，执行 [validation.md](validation.md) 的内容、视觉、技术和交付检查。确认最终文件可重新打开且所有页面完整后，交付时删除工作副本，只保留最终版和原件（目标目录不留工作副本）；如确需回溯，可在删除前把一份带时间戳的恢复点存到目标目录之外。
